# Мини-проект: `httpx` + парсер новостей Kommersant

Эта папка сделана отдельно от основного кода и содержит:
- понятное объяснение, как работает `httpx`;
- минимально рабочий парсер новостей Kommersant (через RSS);
- ноль лишних зависимостей, кроме `httpx`.

## 1) Что такое `httpx` простыми словами

`httpx` это HTTP-клиент для Python:
- умеет **синхронный** режим (`httpx.Client`);
- умеет **асинхронный** режим (`httpx.AsyncClient`);
- поддерживает HTTP/1.1 и HTTP/2, таймауты, заголовки, куки, прокси, редиректы;
- интерфейс похож на `requests`, но современнее для async-задач.

Если совсем кратко:
- `requests` = хорошо для простых синхронных скриптов;
- `httpx` = хорошо и для синхронных, и для асинхронных сценариев.

## 2) Базовые объекты `httpx`

### `Client` / `AsyncClient`

Лучше создавать клиент один раз и переиспользовать:
- это экономит время на повторных TCP/TLS-соединениях;
- удобнее централизованно настроить `headers`, `timeout`, `base_url`.

### `Response`

`client.get(...)` возвращает `Response`:
- `response.status_code` - код ответа;
- `response.text` - текст;
- `response.json()` - JSON (если ответ реально JSON);
- `response.raise_for_status()` - бросает исключение для 4xx/5xx.

### Таймауты

Без таймаутов сетевой код может "висеть". В `httpx` можно тонко задавать:
- `connect` - время на установку соединения;
- `read` - ожидание данных от сервера;
- `write` - отправка данных;
- `pool` - ожидание свободного соединения из пула.

## 3) Sync и Async на пальцах

### Sync

Подходит для:
- 1-2 запросов;
- простых скриптов и cron-задач.

### Async

Подходит, когда:
- много запросов;
- важна скорость за счёт конкурентного I/O;
- код уже асинхронный (боты, API, воркеры).

В этом мини-проекте используется `AsyncClient`.

## 4) Как устроен парсер в этой папке

Файл: `parser.py`

Логика:
1. Создаём `httpx.AsyncClient` с таймаутами и `User-Agent`.
2. Забираем RSS Kommersant: `https://www.kommersant.ru/RSS/news.xml`.
3. Проверяем статус через `raise_for_status()`.
4. Парсим XML стандартной библиотекой (`xml.etree.ElementTree`).
5. Выводим новости текстом или JSON.

Почему RSS для "минимального рабочего":
- структура стабильнее, чем HTML-верстка страницы;
- меньше шансов сломаться из-за редизайна сайта;
- для тестового задания это практичный и надёжный MVP.

## 5) Запуск

Из этой папки:

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python parser.py
```

Опции:

```powershell
python parser.py --limit 5
python parser.py --limit 5 --json
```

## 6) Что важно в реальном проекте

- Добавлять retry-логику (например, при 429/503).
- Логировать ошибки отдельно: timeout, DNS, SSL, bad status.
- Не парсить HTML регулярками там, где есть JSON API или RSS.
- Делать нормализацию данных (даты, дубликаты, ID новости).

## 7) Частые ошибки с `httpx`

- Пытаться делать `response.json()` на HTML-странице (получите ошибку декодирования JSON).
- Создавать новый `Client` на каждый запрос вместо переиспользования.
- Не ставить таймауты.
- Игнорировать `raise_for_status()` и потом долго искать причину пустых данных.
